# 资源兼容与主题支持

更新：2026-09-14。主题按 R33 加入第六类；R34 要求明确版本协议与生态保护的实际边界；R35 的首轮统一管理已实现：原生与标准库存分开读取，安装、更新和卸载调用官方 CLI。固定适配器与混合运行已通过隔离宿主实验；完整操作与限制见 [扩展管理](EXTENSION_MANAGEMENT.md)。

## 版本声明、互操作标准与许可证

| 层次 | 解决的问题 | 当前能说明什么 |
|---|---|---|
| 资源版本 | 用户拿到哪一份发布物 | 固定包版本或提交，不代表兼容某个宿主 |
| DSH 原生接口 | 包如何安装、加载、调用宿主服务 | 官方 CLI、bundle、client、依赖与目标界面各有作用 |
| 兼容声明 | 作者声称支持哪些宿主和依赖 | 声明需与实际测试分别保存；缺失不能推断为全版本支持 |
| dsh-std | 组件与宿主之间如何发现、协商及调用能力 | 自愿采用的社区互操作标准，需对应的协议和宿主适配器 |
| 许可证 | 可否使用、修改及分发 | DSH 与 dsh-std 的项目代码为 MIT；第三方资源保留自身许可 |

官方明确 DSH 仍处于开发者预览，会有破坏兼容性的变化。没有据此承诺所有旧插件在新版继续运行。[官方 README](https://github.com/deepseek-ai/deepseek-harness/blob/master/README.md)

当前上游 `master` 已说明 `engines.dsh` 为宿主 SemVer 范围，`dsh.manifestVersion` 为声明格式版本；`peerDependencies` 描述消费方提供的依赖包范围。官方同时写明：当前安装器和加载器尚未强制执行前两项，不能把字段存在当作拦截不兼容环境的机制。[官方包声明说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/util/package-manifest/README.md)

本仓库锁定的 npm `0.1.5-rc.2` 类型文件尚未包含上述新增公开字段，与上游 `master` 文档有差异。集成结论以实际锁定包为准；不会因为网页上出现了字段就改写旧版宿主能力。

## dsh-std 能保护到哪里

其核心提供协议标识、需求/能力声明与协商；领域协议独立演进，产品由适配器连接。它不是强制官方插件协议，也不是所有插件的自动兼容层。直接使用 DSH 接口或页面结构的插件，需要原生兼容验证；只有使用标准合同且宿主具备相应映射的能力，才可能由适配器吸收变化。项目仍将自身标为早期草案。[dsh-std 说明](https://github.com/Yan-Zero/dsh-std)

本次核查 npm 发布元数据及固定发布提交：

| adapter-dsh 版本 | npm 标签（核查时） | DSH 相关 peer 范围 |
|---|---|---|
| `0.1.1-rc.2` | `latest` | `>=0.1.2-alpha.2 <0.1.3` |
| `0.1.1-rc.3` | `rc` | `>=0.1.2-alpha.2 <0.1.3 || >=0.1.5-rc.2 <0.1.6` |

`rc.3` 的变更说明明确对齐 DSH `0.1.5-rc.2`，因此值得作为当前环境的实验候选。标签会移动，后续实验须固定具体版本；初次研究仅核查声明；本轮已完成该固定适配器的安装与运行实验，范围见下文。[发布与变更记录](https://github.com/Yan-Zero/dsh-std/blob/83eee7fdb3e3096005bb6aeded1e7b6458727d35/packages/adapter-dsh/CHANGELOG.md)、[npm 发布元数据](https://registry.npmjs.org/@dsh-std%2fadapter-dsh/0.1.1-rc.3)

还有两条分发路径：原生 bundle 用 `dsh.bundle` 声明组合配置；标准组件可使用 `dsh-plugin.json`，由已经安装的 adapter-dsh 发现和激活，不必自己声明 `dsh.bundle`。适配器本身才是 DSH bundle。两者都可使用官方 CLI 进行包安装，但安装后的发现与激活不同。[适配器固定版本说明](https://github.com/Yan-Zero/dsh-std/blob/83eee7fdb3e3096005bb6aeded1e7b6458727d35/packages/adapter-dsh/README.md)

## 统一兼容层：已确认的接入范围

R35 将两条接入路径共同纳入我们维护的兼容层。市场、目录和管理流程统一；接入方式与资源类别分别记录，不增加一个与插件、Skill、MCP、Slash、Prompt、主题并列的“dsh-std 类别”。作者采用标准仍是自愿的，原生资源不以改写为标准组件作为收录前提。

| 接入路径 | 兼容层负责什么 | 生效依据 |
|---|---|---|
| 原生 DSH | 通过官方安装机制和公开接口管理；核对宿主、依赖、作用域及实际状态 | 原生加载、注册和功能结果；不能从标准适配器存在推断原生插件受到保护 |
| dsh-std | 固定协议与适配器版本；检查所需能力并经适配器管理组件生命周期 | 协商、激活及目标界面/功能结果；不能仅用原生 Loader 条目判定标准组件未安装或已可用 |

共同管理内容为资源身份与修订、目标环境、依赖、操作进度、失败原因及恢复记录。兼容声明、协议协商、包安装、组件激活、功能实测分别保留结果；仅聚合显示，不把一种结果升级为另一种保证。纯 Prompt 或主题文件继续走各自的使用流程，不强制包装为可执行组件。

实现必须遵守以下边界：

- UI 通过统一管理合同请求操作；两条路径的宿主调用封装在各自适配边界内，不在页面中分散调用宿主或标准运行时。
- 根据经校验的发布物声明选择接入路径。同一发布物提供两种入口时记录本次选用路径，防止重复激活；失败不静默改走另一条路径。
- 安装前检查版本和必要能力。已知不兼容阻止执行；缺少信息或测试显示未知，缺少适配器显示待准备，均不假装已经兼容。
- 更新、停用和卸载核对资源归属与共享依赖；移除标准组件不能顺带删除其他组件仍依赖的适配器，原生与标准组件共存时也不能互相清理注册项。

首轮验收先在固定的 DSH `0.1.5-rc.2` 隔离环境中，各选一个真实原生扩展与标准组件，验证发现、安装、激活、使用、停用、更新和卸载；覆盖混合共存、缺失适配器、能力不匹配、重复入口与失败恢复。之后固定第二个宿主版本重复同一功能测试，再界定跨版本保护范围。测试同时记录资源修订、实际接入路径、协议/适配器版本和环境；对应行为与边界测试接入 `npm run verify`。

首轮实现使用 `adapter-dsh@0.1.1-rc.3`，在 DSH `0.1.5-rc.2` 验证了真实适配器安装、两个测试包混合加载、实际命令、卸载及重启。社区组件广泛实测、单组件启停、更新回归矩阵、第二宿主版本与自动恢复仍未完成。

## 我们的兼容交付要求

Minecraft 类比在本项目中指“明确环境版本、按适用环境选资源、受控更新与可恢复环境”。按 R35，两条接入路径共同接受上述管理和验证，优先复用经验证的 dsh-std 适配实现；不要求社区作者统一改写全部插件。

投稿说明应分别记录以下信息；未知项注明未知：

- 资源版本或提交；目标 DSH 范围及精确测试版本。
- 原生接口或采用的标准、标准版本；若依赖适配器，注明适配器包与版本。
- Web/TUI 等界面、系统、Node.js、父插件与必要服务。
- 作者声明与市场实测分别标注；记录下载、安装、加载、调用、卸载恢复到哪一步。
- 已知冲突及限制。仅支持某版、某界面或某能力时缩小声明，不写“统一生态保护”。

投稿证据仍由正文与 Issue 承载。安装预览已检查固定版本、入口、已声明的版本范围和标准协议；双入口包在可靠隔离前禁止安装。目录中的版本筛选、完整组合回归矩阵和升级恢复仍待完成，不能把“入口已加载”解释为功能或安全保证。

## 主题作为第六类

主题属于市场分类，底层交付不强制统一：

| 形态 | 审核材料 | 生效与恢复验收 |
|---|---|---|
| 主题插件 | 包/声明、DSH 与界面版本、调用的外观接口、截图、字体和图片许可 | 按所用插件路线安装，应用后验证，停用或卸载恢复原外观 |
| 配色或主题文件 | 原始文件、格式、读取它的父插件及版本、显示示例、资源许可 | 按父插件流程导入、切换、移除；不能当作可执行插件安装 |

DSH 的 `ThemeRuntime` 已有主题注册和 token 覆盖接口；本地 `0.1.5-rc.2` 类型中可核对 `register`、`setTheme`、`overrideTokens` 及各自的清理方式。官方仍把第三方主题定位为扩展点，未提供完整主题产品与覆盖完整性保证。因此不推断存在一个所有主题都通用的导入文件格式，也不假定任意第三方主题选择会跨重启持久保存。[官方主题说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/client/ui-theme/README.md)

主题验收增加：声明的深浅模式、文字/输入/弹窗可读性、其他插件共存、重启状态及恢复。覆盖顺序可能影响同一 token；直接修改 DOM 或整体布局的主题需要额外界面回归，不能用 dsh-std 标签代替测试。

当前已加入分类、三语说明、投稿/导出及审核材料；尚无已审核主题条目，页面如实显示等待收录。主题自动发现、安装、应用和恢复仍待逐项实现。模型目录、权重下载和 Cookbook 继续暂缓。
