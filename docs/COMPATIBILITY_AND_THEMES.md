# 资源兼容与主题支持

更新：2026-09-24。版本 `v0.2.0-alpha.1`。官方安装包及真实宿主验收已有本地记录，标准组件完成五次独立启动测试，包括准备后卸载市场；完整发布结果见仓库交付记录及 GitHub Actions。

## 固定基线与两条接入方式

| 项目 | 本项目使用的版本／作用 |
|---|---|
| DSH | `0.1.5-rc.2`，Windows、Node.js 24、Web 界面 |
| adapter-dsh | `@dsh-std/adapter-dsh@0.1.1-rc.3` |
| 标准核心 | `@dsh-std/core@0.1.1-rc.2` |
| 标准清单／生命周期 | `0.1.1-rc.3` |
| 原生 bundle | `dsh.bundle.patch` 提供 profile 组合配置；`dsh.client` 单独声明前端，两者不互相替代 |
| 标准组件 | 由受支持的 `dsh-plugin.json` 声明组件，经已加载的适配器发现和挂载；每个组件无需自带原生 bundle |

这些是固定依赖，不按 npm `latest` 标签推断当前兼容性。原生资源无需改写为 dsh-std 才能收录；采用标准也不保证直接操作 DSH API／DOM 的代码免受上游变化影响。

安装预览检查发布物、入口、`engines.dsh`、`engines.node`、可解析的 DSH peer 范围及标准协议需求。缺少声明显示未知；已知不兼容、缺少必要能力或双入口冲突阻止执行。市场的检查不能被描述为所有宿主版本的安装器都原生强制执行这些声明。

四个官方模块和三条命令是固定 DSH 基线的一部分，可能已由宿主／预设组合，不能为了制造安装成功而重复加载。广泛社区包矩阵和第二宿主版本仍未验证。[官方安装边界](OFFICIAL_PLUGIN_INSTALLATION.md)

## 启停、更新与恢复

原生安装／更新／卸载使用官方 CLI，入口启停通过 profile patch。标准组件使用一个市场管理的发现 Loader，在初始化时将完整启用集合交给公开 SDK，禁用包不进入发现集合。

首次接管可能重载全部标准组件。公开 SDK 无法证明旧发现批次清理成功，因此同一进程内即使替换适配器 active，也保持 **unknown／restart-required** 并阻止下一次标准组件启停。完整停止、重新启动宿主后，稳定 Loader 才可继续接受控制。后续启停只持久化下次启动的目标集合；浏览器在宿主重启后还需刷新。

依赖失败、核心变更或失败／加载中的生命周期仍可能重载。没有模块缓存热替换、按包热卸载或自动清理恢复；目标状态与实际状态分开报告。标准组件在 0.2.0-alpha.1 包中通过五次独立启动与浏览器验收。[扩展管理与恢复](EXTENSION_MANAGEMENT.md)

Skill 支持原文件安装、原生加载／调用、启停、保留文件的移除、更新和恢复。MCP 支持公共 HTTPS 远端与精确 npm stdio 的配置／启停／移除；工具注册不是健康检查，重新配置或换版需移除旧项后明确连接，凭据不自动迁移。这些是独立能力，不由 npm 插件或 dsh-std 的兼容结论覆盖。

## 主题实测

主题发现依据明确的 npm 主题标记、清单或审核元数据，不从 README 文本猜测。目前可安装主题按固定 npm 包绑定走原生或标准接入路径。配色文件可以提案，但不存在所有主题通用的导入格式。

2026-09-14 npm 扫描收录 5 个主题；以下只覆盖三个真实包在 DSH `0.1.5-rc.2`、Windows Edge 的有限验收。安装成功和默认样式可见不能当作所有主题功能通过。

| 精确版本 | 实际结果 | 限制 |
|---|---|---|
| Galactic Opera `0.2.1` | 主题可以应用；属于部分兼容 | 采样文字出现 **1.04:1** 对比度，保留可读性警告 |
| Machine `0.1.3` | 启动受阻，按已知不兼容处理 | 不能因可发现／下载或有主题声明就推荐为可用 |
| `@kubor/dsh-bloom-theme@0.12.0` | 默认 Mist 可用；聚焦切换器后按 **ArrowDown** 打开菜单，再点 Cinnabar，实际配色改变；卸载／重启恢复基线并保留市场数据 | 鼠标无法打开浮动菜单；重复请求本机脚本产生 404。完整往返切换未通过 |

Bloom 的默认、键盘辅助和卸载路径可用，不代表整套验收全绿。其余主题尚未测试；深色模式、全部配色、响应式和完整无障碍没有因这些采样而得到认证。没有通过修改第三方包或添加全局宿主补丁掩盖已知失败。

主题投稿需要精确包版本、目标 DSH／界面、作用方式、父插件（如有）、深浅色示例、字体／图片许可及应用／恢复步骤。重点检查正文、输入、菜单、弹窗、其他插件共存与重启恢复。自定义 DOM／布局的主题尤其需要实际界面验证。
