# R35 首轮统一扩展管理验收

日期：2026-09-14。环境：Windows、Node.js 24.16.0、pnpm 12.3.4、DSH 0.1.5-rc.2、Edge 无头浏览器。代码在原有开发挂载方式中运行，未改上游源码或用户正式 profile，未使用模型付费凭据、未发布仓库。

## 已实现与实测

| 边界 | 验证结果 |
|---|---|
| 发布物 | 固定 npm 身份、SRI、根清单、入口存在性、声明与包版本一致；预览不导入代码 |
| 兼容检查 | DSH/Node 范围、可解析的 DSH peers、实际标准清单定义与协议协商；拒绝缺失能力及双入口安装 |
| 执行器 | 真实 Node 子进程参数、官方 CLI、精确版本、禁用脚本、独占锁、指纹复核、备份与日志、执行后状态核对 |
| 失败 | 外部修改、并发进程、错误退出、假成功、无效路径和包参数均有行为测试；不将复制锁文件视为完整回滚 |
| 宿主 | 真实公开 adapter-dsh@0.1.1-rc.3 经市场执行器安装；明确标记的原生与标准测试包同时加载，原生端点返回 42、标准命令返回预期文本 |
| 卸载 | 官方 remove 移除原生测试包；重启后标准组件与共享适配器保留，并再次运行标准命令 |
| UI | 当前 profile 读取、中英日切换、窄屏、不兼容阻止确认、网络响应丢失时同一请求重试 |

首次界面验收发现浏览器原生 fetch 的接收者绑定错误，修复后通过实际浏览器回归。DSH Fetch 通道同一路径只能注册一次且流式请求不能用于无正文 GET，读写路由现分别采用 `/extensions/read` 与 `/extensions`；实际宿主验收覆盖此边界。

原有来源下载改为每批最多四个文件并行，逐文件散列核对与归档顺序保持；公开 GET 只对连接/超时失败重试一次。浏览器测试在 HTTP 错误时立即报告来源错误，不再一直等待不会出现的下载事件。网络限流和不可达仍会如实使联网验收失败。

测试包为仓库内 fixture，不是新收录的社区资源。此次没有完成任意标准组件、所有资源类型、第二个 DSH 版本、热启停、自动恢复或商城独立发布包的验收。名称版本安装仍由 pnpm 再次获取包，预览 SRI 不等于执行字节与全部传递依赖已固定。详细使用与恢复边界见 [扩展管理](../EXTENSION_MANAGEMENT.md)。
