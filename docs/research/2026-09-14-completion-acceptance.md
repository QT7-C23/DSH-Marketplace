## 实际使用与管理

- 原生插件与标准组件能在同一宿主运行。原生入口经过停用、重启、启用、调用、移除及再次重启检查。
- Skill 原文件安装、原生工具读取、停用/启用、更新、保留副本移除及历史恢复有文件系统与真实宿主证据；未改写作者正文。
- Microsoft Learn MCP 注册原生工具后真实查询返回 Blob 文档；跨进程启停与移除已验收。注册状态不等于持续连接健康。
- `/plan` 与 `/plan off` 通过原生接口执行，保留原有输入草稿和附件引用。Prompt 追加由用户确认，不自动发送。
- Galactic Opera 0.2.1 可安装/应用/移除，但宿主按钮对比度存在问题；Machine 0.1.3 启动失败，固定版本阻止安装；Bloom 0.12.0 键盘切换可用，鼠标交互有问题，固定版本提示。其他大包可能超过预览限制。
- 标准组件采用受管完整启用集合；首次接管可能重载旧组件，必须冷启动后确认。旧清理状态无法证明时保持未知并阻止继续切换，不靠新适配器空清单宣称清理成功。
- 安装操作共用锁、备份和日志；恢复失败保留记录。没有通用热卸载、内存模块回滚或不受限制的自动恢复。

`0.2.0-alpha.1` 标准组件经过五次独立宿主进程与 Edge 验收：首次接管保持未知；冷启动后 A 停用且 B 可用；重新启用不改变当次运行而在下一次启动生效；停用 A 更新到 2.0.0 后仍不导入，外部新增组件可用；执行包内卸载准备、官方移除市场后，原组件命令与浏览器入口仍能运行。证据保存在本机忽略目录 `artifacts/dsh-integration/standard-Tenzha/`。

卸载准备先预览原停用列表，按同一配置指纹确认；恢复上游发现可能重新启用这些组件，必须明确接受。配置有改动、归属不明确或现有操作未恢复时拒绝写入，只移除市场拥有的块并保留备份。不自动判断或停止用户宿主，操作前须停止 DSH。

另确认 dsh-std adapter 0.1.1-rc.3 的上游限制：先加载声明 CommandRuntime 依赖的组件后，后续组件可能因共享端点协商失败而无法启动。当前验收的命令提供组件不消费该接口；未借此声称所有标准组件组合都兼容。

## 社区与统计

六类提交均需署名、许可与对应固定资源绑定；审核目录支持独立 GitHub Skill 和原生 MCP。撤下规则按稳定身份跨来源生效，失败刷新和重启后仍保留；安装记录和用户本地副本继续可管理。成功同步空策略后可以恢复收录。

GitHub Star 是整个仓库；npm 是带时间范围的上月整包下载量；本机下载记录表示文件准备成功。零值、未知值与过期缓存分别显示。收藏和评分是个人记录，不称公共人数或均分。npm 请求有并发、队列和缓存上限，页面离开和宿主关闭会取消无消费者的请求。
