## 3. 注册登录目前做什么

当前是独立的本机社区账户，不是 DeepSeek 模型账户、API Key、DSH 工作区账户，也不是已上线的互联网社区。其作用是识别投稿作者、限制谁能更新或撤回，隔离私有草稿和保存副本，并记录每账户一份评分。同一社区服务的不同浏览器可用同一账户；跨设备公共同步尚未部署。

实现目前对社区写入统一要求登录，因此保存、下载、投稿、反馈和评分都受此约束。浏览公开条目和使用 Prompt 本身不要求市场账户。身份对公开投稿和个人评分有用，但不意味着本机收藏和公开资源下载也需要注册。

## 4. 推荐的账户边界

| 用户动作 | 建议是否需要市场登录 |
|---|---|
| 浏览、搜索、详情、下载公开资料 | 不需要 |
| 安装公开资源、使用 Prompt、配置本机能力 | 不需要；资源自身的 API 凭据或外部服务授权另行处理 |
| 本机收藏、私有草稿、管理本机资源 | 不需要，先保存在本机 |
| 向社区发布、维护自己的投稿、评分和反馈 | 需要可确认的身份，操作发生时解释用途并引导 |
| 跨设备同步收藏与草稿 | 需要账户及真实同步服务；是可选能力 |

免登录的本机收藏不伪装成公共社区收藏人数；未来登录后由用户选择同步，再按社区账户去重。公开下载不依赖账户统计，也不能宣称次数等于独立人数。评分继续显示人数，仅限制同一账户一票，不承诺能阻止多个账户刷分。

本轮建议先弱化密码注册入口，保留作者身份服务。未来可评估 GitHub 等已有身份登录，但具体提供方尚未决定。调整不会删除现有账户或绕过作者权限，也不移除 DSH 自己的宿主访问认证。

## 5. 待评审的页面组织

顶部：资源市场标题，发现 / 我的资源，次级的“分享资源”和“来源设置”。下方立即是全宽搜索、五类筛选和排序。发现区使用紧凑卡片，依次展示图标、名称、用途、来源和简短统计；详情显示当前类别的主动作、说明、版本和评价。我的资源内部再区分已安装、已保存/收藏与待更新，按真实状态展示。

实施时先完成原生样式与首页层级，再拆分本机数据与社区身份。验证要求：宿主深浅主题和字号调整同步生效；窄屏搜索与主动作可见；游客能完成公开资源获取；投稿仍有作者权限；登录、退出和网络失败不丢失本机资料；收藏/下载/评分口径保持真实。当前 34 项测试证明旧实现行为，不能直接证明这套新方案已完成。
