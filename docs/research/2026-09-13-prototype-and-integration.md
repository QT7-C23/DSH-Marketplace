# 第一版交互原型与 DSH 接入核查

日期：2026-09-13。范围：本机可点击原型、自动化验证、一个公开来源读取和 DSH 固定提交的接口核查。用户授权开始原型工作；本轮没有对外发布、改动现有 DSH 环境或调用模型。

后续进展见 [真实宿主接入实验](2026-09-13-host-integration.md)。本文保留前轮核查时的证据状态，不作为当前宿主实现状态的唯一依据。

## 1. 交付与验收范围

启动入口见 [README](../../README.md)。原型覆盖发现、详情、我的资源、分享、我的发布、来源、更新与恢复、任务草稿八个视图。首发类别保持插件、Skill、MCP、Slash、Prompt；模型目录、下载、Cookbook 与主题仍暂缓。

| 流程 | 本轮实现 | 仍未实现 |
|---|---|---|
| 发现资源 | 五类代表样本、搜索、筛选、空结果、用途和来源说明 | 多源资源索引、去重、完整自动同步 |
| 分享与维护 | 文本编辑、文件导入、私有草稿、本机投稿、作者新版、撤回、反馈 | 在线账户、服务端权限、包上传与社区审核 |
| 使用 Prompt | 必填项、重复变量替换、完整预览、保留已有任务草稿、复制 | 插入真实 DSH 会话及模型结果检验 |
| 保存与更新 | 独立版本副本、明确更新、作者撤回后副本仍可使用 | 用户自行编辑副本后的合并规则 |
| 其他四类 | 配置、缺依赖、未授权、添加和移除的交互演示；样本 Slash 与插件共用状态 | 真实安装、加载、执行、健康检查与环境恢复 |
| 本机数据 | 当前浏览器持久化，异常存储阻止覆盖原始记录 | 跨浏览器同步、多人并发、正式迁移与备份产品流程 |

原型内的两个身份用于观察作者与使用者的区别，不能作为真实身份认证或防越权机制。非 Prompt 投稿目前接收用途、说明与 HTTPS 发布地址；TXT/Markdown/JSON 导入仅提供文本内容，不等于完整包或 Skill 目录上传。

## 2. 已核查的接入点

下列 DSH 材料固定于提交 `c291e7961a515f6d7af9304e7fd1d257929aef26`。它是实验候选基线，不代表所有已发行版本。结论分为源代码证据和乙方推断，尚未启动该版本宿主。

| 问题 | 源码证据 | 对实施的影响 |
|---|---|---|
| 能否提供自己的前端模块 | 包声明 `dsh.client`、`platform: 'web'` 与 `./client` 导出，模块注册器负责浏览器组合和资源提供 [S1] | 有扩展模块路线；还要制作最小包验证构建、加载、卸载和宿主依赖 |
| 能否提供市场入口 | 侧栏声明 `sidebar.panellist`，列表 ID 对应主面板，包含标签与顺序元数据 [S2] | 可据此验证侧栏入口；主面板注册、路由恢复与生命周期仍须实测 |
| 能否把 Prompt 放进会话 | 会话插槽公开 `useInput` 和 `inputActions`，无会话时动作可能不存在；输入合同有 `setDraft(text)` 与带版本跨度的文本插入事件 [S3][S4] | 存在公开接入点。`setDraft` 替换全文，不能直接用来保证追加时保留引用、附件和并发输入；优先验证会话内模板入口和受保护的插入路径 |
| 是否已有社区上传存储 | 已读上传路由要求 `sessionId`，调用会话文件上传服务 [S5]；模块 `/plugins` 路由提供前端资源 [S1] | 这些证据不能证明现成的社区投稿后端。账户、作者权限、版本、审核与公开目录仍按本产品负责建设估算 |

这里没有把内部编辑器句柄当成跨插件接口，也没有用 DOM 注入替代宿主合同。全局市场选择的目标会话可能在填写期间变化，需明确锁定对象和过期处理；不能将本机原型中一个独立文本框的成功直接等同于 DSH 插入成功。

## 3. 真实来源读取

本机适配器于 `2026-09-13T08:10:32.555Z` 成功请求 [Anthropic Skills 目录 API](https://api.github.com/repos/anthropics/skills/contents/skills)：读到 **19 个目录**，`internal-comms` 存在。这是指定路径的一次响应，数量会变化，也不表示 19 个资源均适配 DSH。

请求只读固定公开地址，设置超时并校验列表结构；不接受任意上游地址，不传输投稿、任务文本或用户凭据。界面首次访问读取一次，可手动刷新；失败保留上次成功时间与数量。尚未获取完整目录内容、计算版本、去重或把全部资源加入市场。自动化浏览器测试使用固定的 12 个目录作为替身，不能拿它作为实际来源数量。

## 4. 验证结果

统一命令为 `npm run verify`。本轮环境：Windows、Node.js 24.16.0、Playwright 1.62.1 和本机 Microsoft Edge。

- 14 项测试通过：9 项状态逻辑、2 项适配器/HTTP、3 项真实浏览器流程；覆盖私有草稿、作者维护、模板缺项与字面替换、版本副本、撤回、任务保留、安装关联、错误与恢复、来源失败、无效地址及损坏存储。
- 浏览器验证了搜索与筛选、投稿的安全文本预览、发布与版本更新、刷新后的草稿、Esc 关闭及焦点归还、深浅主题、390px 窄屏和字阶放大至 200%。文本放大测试不等于完整浏览器缩放认证。
- 静态门禁检查 UTF-8、行尾空白、语法、相对文档链接、生成文件一致性、模块依赖方向，以及深浅主题共 26 组语义颜色对比度。
- 检查发现并修复：从“我的资源”打开时误取作者最新版；输入框边框对比度不足；部分损坏的存储集合未在渲染前拒绝。行为修复先观察测试失败，再回归通过。
- 截图位于忽略目录 `artifacts/`：`discovery-desktop.png`、`discovery-mobile.png`、`discovery-dark.png`、`prompt-preview.png`；已人工查看。它们记录原型外观，不证明 DSH 宿主支持。

未开展屏幕阅读器完整审核、跨浏览器矩阵、真实用户访谈或模型输出质量测试。父 Git 仓库的 CI/提交 hooks 尚未接入本项目验证；没有修改父仓库配置来制造自动门禁已生效的印象。

## 5. 下一阶段建议与通过条件

1. **隔离 DSH 宿主验证。** 固定版本、独立配置与工作区，先加载一个市场入口和会话内 Prompt 入口。verify：可进入、退出、卸载；已有文字、引用和附件保留；切换会话、无会话和宿主忙碌均有确定结果，模板不会自动发送。
2. **建立真实社区最小后端。** 建议先用一项服务和一个数据库承载投稿元数据、Prompt 版本与作者权限，再按真实包大小增加对象存储。verify：两个真实账户隔离、作者发布被另一账户发现、版本和撤回语义保持、网络失败可重试。部署位置、账户方式、数据留存和持续费用另给比较，不把本机身份选择器沿用为认证。
3. **完整来源同步与其他资源接入。** 同步一个固定来源的实际条目和版本，然后按所属包处理插件/Slash，再做完整 Skill 目录及 MCP 配置。verify：去重、更新、失败、移除和真实调用分别有证据；不以目录可读取代替资源可使用。

原型阶段的轻量浏览器结构不决定正式宿主框架。界面和状态语义可以复用，DSH 前端接入应遵循其模块与插槽合同；本机模拟安装记录不能迁移为真实安装事实。总工期与报价仍缺少宿主实验、服务部署及资源格式支持矩阵的依据。
